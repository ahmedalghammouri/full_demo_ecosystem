Material balance across the line refreshes every 1.5s
Each machine counts in its own unit — the filler in inners, the cartoner in cartons, the palletiser in pallets. Converted through the product’s packaging ladder they become comparable, and each row’s Diff is what the machine before it made minus what this one has handled. A steady positive gap that is larger than the work sitting inside the machine is a counter missing pulses.
Reconciled line refreshes every 1.5s
One counter can be wrong; a whole line cannot, because material is conserved. What left a machine either entered the next one or is still on the conveyor between them. So a gap no larger than that conveyor is physics and is left alone — and only what exceeds it is treated as a miscount. Corrections credit the minimum the line forces to be true, never more, and one that hits its ceiling is clamped and reported rather than absorbed.
Counter health measured on the live signal
A miscounting sensor is silent — it does not error, it just reports a smaller number. Two things give it away. If the counted level never lasts more than one sample, its real width is below the sample interval and the total is a floor, not a count. And two counters on one machine watch the same product, so if one reports a fraction of the other, the signals are different shapes and the answer is at the sensor, not the poll rate.

Configuration gateway only — not editable from the web app
Conveyor capacity is one belt — the run from that machine to the next one only, never a total across several. Each machine is compared with its own neighbour, so the chain builds itself; adding them up would count a belt twice. Enter it in whatever unit you counted it in: “3 cartons” is typed as 3 with CARTON selected, and the ladder converts it. Leave it empty and that link is left unbalanced: an unmeasured conveyor is never assumed to be empty.
Transit is seconds for one unit to travel that belt — it does not affect the correction, only when the line counts as drained. Max corr % is the ceiling: past it the correction is clamped and reported instead of applied. Apply records the correction against the job order; with it off, the balance is measured and shown and nothing is written.

What each machine is allowed to count applies on the next cycle — no restart
Two guards, and they do different jobs. Debounce refuses an edge arriving sooner than a product possibly can — it removes contact ring at the source, which is the real cure. At 45 parts a minute the fastest true gap is 1333 ms, so 200 ms kills every ring and cannot touch a product. Zero is off. Tolerance holds a whole minute to the machine’s design rate plus this allowance; anything over is trimmed, rejects first. It is a net, not a cure — it DISCARDS measured counts, so what it removes is shown in the last column. Leave it blank for no cap.
A trim figure that stays high means the counter is still over-counting. Tighten the debounce, not the tolerance — the tolerance only hides it.
